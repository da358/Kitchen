Glow first-paint (Issue 2) — three architectures

"Simulate drag-over" lights the checklist row (.match) and the ticket glow (.drag-over) from the same event, exactly as the game does — on iPad Safari / Blink, watch whether the glow lags the row. "Reset render state" replaces the ticket node with a fresh copy so the engine must rebuild its layers, reproducing a true first paint; without it, second and later hovers are always fast. A = shipped five-pass filter (verbatim CSS). B = cheap tier: 3 passes + will-change: filter. C = the proposed fix: two permanently-present glow layers (green/copper) behind the ticket, each a duplicate of the torn-edge silhouette carrying its drop-shadows at all times, toggled by opacity only — compositor-only, so it should be instant everywhere, and it verifies here that the glow still traces the torn edge. "Show ready glow" toggles the persistent copper state for comparison. This layer is also the natural home for future celebration effects.
